# Solana announcement watcher

Скрипт отслеживает публикацию адреса Solana-токена в Telegram, на сайте и в X.
Он извлекает адрес из сообщения или ссылки, проверяет mint через RPC и может
отправить его отдельным сообщением в настроенного Telegram-бота.

Задача появилась перед анонсом токена: адрес могли выложить на любой из трёх
площадок. Проверять их вручную и копировать контракт в другой чат означало
терять время. Здесь источники работают параллельно, а общий SQLite-журнал
не даёт повторно отправить один адрес после дубля публикации или перезапуска.

## Как работает

```text
Telegram: новые сообщения и правки ─┐
Сайт: HTTP-опрос ──────────────────┼─ адрес → проверка mint → журнал → Telegram-бот
X: официальный API ────────────────┘
```

Telegram userbot использует Telethon. Он проверяет текст, подписи к медиа,
скрытые ссылки и URL-кнопки. Сайт опрашивается раз в секунду, X — раз в 15 секунд;
оба интервала задаются в конфиге. HTTP-запросы учитывают ETag, Last-Modified
и ограничения частоты запросов.

Base58-строка должна декодироваться в 32 байта. Перед отправкой RPC проверяет
программу-владельца аккаунта Token/Token-2022 и тип `mint`. Пока RPC не видит
аккаунт или отвечает ошибкой, кандидат остаётся в очереди на диске.
Несколько новых адресов в одной публикации считаются неоднозначным сигналом.

По умолчанию включён **dry-run**: находки записываются в журнал, сообщений нет.
Режим LIVE допускает одну попытку отправки за всё время существования выбранной
базы `STATE_DB`. Резервирование происходит до сетевого запроса. При таймауте
результат отмечается как `unknown`, автоматической повторной отправки нет.

## Запуск

Python 3.12+. Создать окружение, установить зависимости и заполнить локальный `.env`:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В PowerShell окружение активируется командой `.venv\Scripts\Activate.ps1`,
а файл копируется через `Copy-Item .env.example .env`.

Для Telegram нужны собственные `TG_API_ID` и `TG_API_HASH` из
[my.telegram.org](https://my.telegram.org), затем локальный вход:

```sh
python -m watcher login
python -m watcher run
```

Номер, одноразовый код и пароль 2FA вводятся скрыто в терминале. Сессия сохраняется
локально. При запуске userbot подписывается на указанные публичные каналы.

Для отправки нужны `TRADING_BOT` и `RPC_URL` Solana mainnet. Получателем может быть
Telegram-бот; отправка в каналы и группы сейчас не реализована.

```sh
python -m watcher run --live
```

Получатель получает только адрес. Если у торгового бота включена Auto Buy,
это сообщение может вызвать покупку. Скрипт подтверждает доставку сообщения,
а не результат сделки; кошельком и подписью транзакций он не управляет.

Дополнительные команды:

```sh
python -m watcher website-once       # один HTTP-запрос к каждому сайту
python -m watcher status             # локальный журнал отправок
python -m watcher extract 'CA: ...'  # извлечение адресов без сети
python -m unittest discover -s tests -v
```

## Ограничения

- Первый запрос сайта и X сохраняет исходное состояние и пропускает старые адреса.
  Запускать мониторинг нужно до анонса. Dry-run находки не отправляются позже в LIVE.
- Telegram слушает новые события; пропущенная во время отключения история не дочитывается.
  OCR изображений и видео отсутствует.
- JavaScript сайта не исполняется. Если контракт появляется только через клиентский API,
  нужно указать публичный GET endpoint в `WEBSITE_URLS` или адаптировать запрос.
- X требует `X_BEARER_TOKEN` с доступом к таймлайну. Его интеграция проверена моками,
  без подтверждения работы на реальном API-аккаунте.
- RPC должен быть подключён к нужной сети. Проверка mint не подтверждает принадлежность
  токена бренду. Скорость обнаружения и место в очереди покупок не гарантируются.

В репозитории 21 тест: извлечение адресов, гонки источников, исходное состояние,
перезапуск, очередь RPC и неопределённый результат отправки. HTTP-адаптер также
проверяется на локальном сервере. Тесты не отправляют сообщения в настоящий Telegram.
